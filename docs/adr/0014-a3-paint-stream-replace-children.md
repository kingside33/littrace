# [A3 修复] 卡片流重画改为整体替换子节点列表,瞬态节点不参与复用

- 日期:2026-11-18
- 状态:已接受

## 背景

`paintStream()` 只按 `[data-card-id]` 收集与清理节点,而 `renderStage` / `renderEmpty`
产生的 `.lt-stage` / `.lt-empty` 不带该属性,于是既不参与复用也永不被移除,paint 只会
不断 append 新的。回答到达后 `panelStatus` 变 ready、本轮不再 push 进度行,但上一轮那条
`progress=35` 的进度行仍留在流里;每问一次再加一条。首次 `openPanel` 的空态提示在提问后
也仍留在流顶部。评审指出这直接推翻了 PR 正文里「进度行只占一行」的验收待办。

## 决策

`paintStream()` 改用 `stream.replaceChildren(...ordered)` 整体替换子节点列表;卡片节点
仍按 `[data-card-id]` 复用同一个对象,不带卡片 id 的进度行与空态提示每轮重画、旧的自然
消失。顺带保存 / 恢复 `scrollTop`。

## 备选

- **备选 A:为每个节点打上可识别属性再逐个移除**。不选:`replaceChildren` 一次到位,
  不需要给瞬态节点额外加 data 属性,也不会出现「某类节点忘了打属性」的再次稀疏。
- **备选 B:每次重画前先清空容器**。不选:会重建所有卡片节点,`<details open>` 的展开
  状态和滚动位置都丢失,反而弄乱了 append-only 想要保住的「历史不被重绘」。

## 后果

卡片节点仍是同一个 DOM 对象,展开状态与滚动位置保持;瞬态节点(进度行 / 空态提示)每轮
重画。代价是一次 `replaceChildren` 的重排,但节点复用后实际移动的只是少数;这换来了
「进度行只占一行」在代码层而不是在渲染时自然成立。重画时还要把流里的临时提示节点一并
带上,否则紧随其后的重画会把刚显示的提示抹掉。
