# [S3] 版本端点测试断言 pyproject 兜底值而非硬依赖包元数据

- 日期:2026-11-18
- 状态:已接受

## 背景

接续上一条决策时发现:原用例直接断言 `metadata.version('littrace')`,而同一仓库的
`pyproject.toml` 明确声明支持免安装跑测试。在该模式下 `metadata.version` 会抛
`PackageNotFoundError`,用例与它所服务的「单出处」设计自相矛盾。CI 里恰好装了包所以
一直是绿的 —— 这是潜伏缺陷,不是通过。

## 决策

已安装分支用 `skipTest` 优雅降级(跳过理由写明由兜底用例覆盖该模式),并新增独立用例:
patch 掉 `metadata.version` 让它抛 `PackageNotFoundError`,走兜底路径,期望值直接解析
`pyproject.toml` 的 `[project].version`。两种运行模式都被覆盖。

## 备选

- **备选 A:保持原样**。不选:依赖 CI 环境里恰好装了包;免安装模式(仓库明确支持)下
  会红,而且红的原因与被测代码无关。
- **备选 B:整体删掉该断言**。不选:降低覆盖强度,把一条潜伏缺陷换成一条空白。
- **备选 C:mock 出一个固定版本字符串作期望值**。不选:期望值即第二份版本常量,又回到
  双出处问题。

## 后果

测试在已安装与未安装两种受支持模式下均成立。用例经变异测试证实能捕获兜底分支回归:
移除兜底后该用例失败。日后改 `pyproject` 版本号不需要同时改测试。
