# [AGENTS] ADR 目录以编号纪律正文加三列空索引表起步

- 日期:2026-11-18
- 状态:已接受

## 背景

仓库首次引入 ADR 纪律:要把机制选型、契约、流程与验收方法留存成可检索、可引用的正式
文档,而不是散在 PR 正文和评审线程里。需要先放下目录骨架 —— 文件位置、编号规则、索引
格式 —— 但此刻还没有任何一条已落盘的决策。

## 决策

新建 `docs/adr/README.md`:正文写编号纪律(一个决策一个文件、`NNNN` 从 0001 起递增、
不复用、不跳号占位、定稿不改写、修订开新 ADR 并引用旧号、DecisionRecord 在实现 PR 里
上报),索引表以「编号 / 标题 / 一句话」三列空表起步,不预填任何行。

## 备选

- **备选 A:先造一个 0001 示例 ADR**,让目录看起来「有内容」。不选:示例不是真实决策,
  会占据一个编号并迫使命中它的读者去分辨真假;更糟的是它暗示目录里可以有凑数的文件。
- **备选 B:预填索引行或留 `NNNN-<slug>.md` 占位文件**。不选:与「不跳号占位」的纪律
  直接冲突 —— 纪律刚写下就被自己的骨架破掉。

## 后果

ADR 目录结构即刻可用,后续批次按同一格式追加即可。索引为空是**预期中的前瞻状态**,
第一个 ADR 批次落盘后即自洽;这不算缺陷,也不需要额外解释。维护者新增 ADR 时只需
遵守正文纪律并补一行索引。
