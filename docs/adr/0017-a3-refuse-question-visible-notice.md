# [A3 修复] 拒绝新提问时给出可见提示,输入不再被静默吞掉

- 日期:2026-11-18
- 状态:已接受

## 背景

`run()` 在 `mount.timer !== null` 时静默 return,而 form 的 submit 处理器在调用它之前
已经 `input.value = ""`;阶段进行中再提交第二个问题,问题既没变成卡片也没任何提示,用户
输入凭空消失。划词路径同理,选中文本被丢弃。评审指出这违反仓库措辞纪律的「绝不静默
失败」。

## 决策

`run()` 改为返回 boolean 表示是否真的开始;拒绝时 `showNotice()` 在流里放
`role=alert` 提示(`reader-panel-wait`)。form 的 submit 只在返回 true 时清空输入;
划词被拒时把选中文本写回输入框;新增 `syncFormState()` 在阶段进行中禁用提交按钮并替换
placeholder。

## 备选

- **备选 A:保持静默 return,只在文档里注明一次一问**。不选:直接违反仓库措辞纪律
  「绝不静默失败」,而且用户丢的是自己手打的问题。
- **备选 B:禁用提交按钮但不解释**。不选:一个灰掉的按钮不告知原因,用户只会反复点。

## 后果

提交按钮在进行中置灰、placeholder 说明原因,误提交的输入原样保留,划词被拒时选中文本会
回填到输入框;用户总有下一次机会。代价是每拒绝一次就在流里多一条 `.lt-notice`,需要
`paintStream` 重画时保留它(见 0014),否则提示会被紧随其后的重画抹掉。
