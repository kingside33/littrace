# [U2] 每条评审发现都配可脱离 Zotero 执行的测试锚定,并验证锚定真的会红

- 日期:2026-11-18
- 状态:已接受

## 背景

U2 的多数评审发现是特权上下文 / 钩子时序问题(同条目重绘跳过 `onRender`、多窗口
mount 串扰、离线态不自愈)。按仓库纪律,特权上下文与真机行为不能写假 Zotero 单测;
但如果只改代码不加锚定,同类问题会原样再犯,而且没有任何门禁能发现。

难点在于:「不写假单测」与「必须带测试锚定」同时成立。

## 决策

服务端与纯逻辑类发现的断言真实执行。DOM / 钩子时序类发现(评审第 3、5、6 条)用
「函数体文本锁定 + 可执行行为断言」的混合锚定:纯逻辑部分(状态机、`onRender` 是
唯一绘制路径)走真实断言(`tests/test_plugin_sections.cjs:316、692`),接线部分按
源码文本锁定,并把仍需真机确认的部分显式留在 pending。

提交前把源码回滚到修复版本之前跑一遍,确认新增断言确实失败(9 条测试转红),再恢复。

## 备选

- **备选 A:只断言「离线态文案存在」而不锁行为**。不选:改文案也能通过,发现等于
  没被锁住。
- **备选 B:在 node 侧 mock Zotero 重放钩子序列**。不选:AGENTS.md 明确特权上下文
  不写假单测,且需要装配大量 DOM / 元素基类,维护成本高于收益。

## 后果

每条发现都有可在无 Zotero 环境下执行的锚点,回忆式重构也会被文本锚点挡住。修复
3 / 5 / 6 关于 Zotero 源码的推论仍未真机验证,已列入 pending——锚定证明的是我们的
代码符合推论的接口契约,不是推论本身正确。
