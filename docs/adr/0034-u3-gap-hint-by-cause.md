# [U3] 缺口卡片按成因给提示,而非共用「无证据」文案

- 日期:2026-11-18
- 状态:已接受

## 背景

面板底部的缺口灰块原先共用一条固定提示:「这一问没有可定位页码的原文证据,
只保留问题本身」。

但这个灰块被三种互不相同的成因复用:检索 warning(例如「向量已停,当前用关键词
结果」)、截断提示、以及真正的「没找到证据」。共用的后果是**自相矛盾**:证据
卡片正常显示在上方时,下方却写着「没有可定位页码的原文证据」,直接否定了上面的
结果。

另外 `rows.length` 是服务端按 `k` 截断后的**返回条数**,不是命中总数——
这一侧根本无法知道总数。

## 决策

缺口携带**成因**,卡片视图按成因选固定提示:

```
GAP_HINTS = { EVIDENCE, WARNING, TRUNCATED, LINEAGE }
```

(`plugin/src/readerPanelCore.mjs:466`;归一化在 `normalizeGap()`,兼容纯字符串
入参并默认 `EVIDENCE`)。

截断文案只陈述「本次只取回 N 条,已展示前 M 条」
(`plugin/src/readerPanelCore.mjs:1164-1170`),**不断言命中总数**。

## 备选

- **备选 A:所有缺口继续共用一条提示**。否决:自相矛盾——用一条「没有证据」
  的文案去否定它上方正在显示的证据。
- **备选 B:去查真实命中总数,再写一条准确的截断文案**。否决:当前端点不返回
  这个字段,需要服务端新增字段;而这属于另一个 PR 的范围,且面板并不需要这个
  数字才能把话说清楚。

## 后果

灰块与成因一一对应,测试可直接断言 `hintKey`。代价是中英文语言包各多三条文案
(`plugin/addon/locale/{zh-CN,en-US}/addon.ftl:19-23`);缺口入参多一种对象形态,
但保留纯字符串兼容,旧调用点无需改动。
