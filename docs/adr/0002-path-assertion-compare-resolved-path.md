# [C1] 路径断言改比较 resolve() 后的 Path,而不是比较字符串拼写

- 日期:2026-11-18
- 状态:已接受

## 背景

Windows CI 上唯一的失败点在 `tests/test_documents.py` 的「移动后再次 register 复用同一
document id」用例。`register()` 内部会对传入路径做 `Path(path).resolve()`,而 CI runner
的临时目录带 8.3 短名(如 `RUNNER~1`),`resolve()` 会把它展开成长名;断言右侧却是
`str(moved)`,保留着构造时的短名写法。两侧指向同一个文件,但字符串不相等。

被测行为是「同一个文件被移动后仍被识别为同一 document」,与路径的字符拼写无关。断言
选错了比较对象,所以要在几种等价性比较方式里挑一个。

## 决策

断言改为 `self.assertEqual(Path(again['path']).resolve(), moved.resolve())`,并在注释里
写明原因(register 会规范化路径、Windows 短名与长名指向同一文件)。同时保留
`again['id'] == registered['id']` 的 id 断言与前后页面计数断言,一个字都不弱化。

## 备选

- **备选 A:改用 `os.path.samefile()`**。语义上完全正确,但不选:对不存在的路径会抛
  `OSError`,失败信息也不如两个 `Path` 直接相等来得直白;这里要断言的是「指向同一文件」,
  而 `resolve()` 后的 `Path` 相等正是它的可读表达。
- **备选 B:在文档侧把短名规范化后再存**。不选:为了迁就一条断言去改生产代码,把测试
  的规范化责任推给了被守护的实现。
- **备选 C:只断言 `again['id']`,删掉路径断言**。不选:直接削弱被测行为,路径错乱这类
  缺陷将不再被捕获。

## 后果

检测力度不变:路径仍必须指向同一个文件,依赖关系与页面计数断言均保留。在非 Windows 上
`resolve()` 对已规范路径是一比一等价的,不会引入新的平台差异。写新断言时注意:凡是
「是不是同一个文件」的语义,统一比较 `resolve()` 后的 `Path`,别比字符串。
