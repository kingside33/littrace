# [流程] 错题本单文件 + Seen 阈值升级,由每周周报 issue 驱动

- 日期:2026-11-20
- 状态:已接受

## 背景

ADR 记录「做过的决策」,但没有地方记录「犯过的错」。`AGENTS.md` 每次会话
常驻,不能用来堆教训正文;把教训直接写进去会让常驻上下文持续膨胀,而且没有
删除与升级的出口。

#82 / #83 因此引入了按本仓库规模裁剪的错题本:单文件 `docs/lessons.md`、
四字段条目(`类` / `Seen` / `为什么` / `证据`)、16 KiB 上限,
`scripts/check_lessons.py` 校验格式、编号、指针目标与隐私,CI 在
`python-lint` job 里跑一次。参考的是 Tavotto 的 `docs/rules/repo/lessons/`,
但去掉了它的分层拆文件与夜间自动复盘。

合入后暴露了两个问题:

- **没有 ADR。** #83 的 DecisionRecord 写「后续批次按仓库纪律补 ADR」,此后
  合并的多个 PR 都没有落盘,决策只在 PR 正文里。承诺没有载体就会消失,这本身
  是错题本该记录的那类错误。
- **只有格式门禁,没有流程。** 机制真正的两条出口——同一条目在 3 个不同日期
  出现后升级为硬规则、60 天不复发则删除——只以 `check_lessons.py --due` 的
  形式存在,**仓库里没有任何工作流、脚本或模板调用它**。GitHub 上唯一相关的
  运行是 `python-lint` 里的一个 step,看板不会把它读成「错题本在运行」。
  条目数自引入后没有增长,也没有任何东西提醒某条已经到期。

结果是一个通过格式校验、但不会产生任何升级或删除动作的文件。

## 决策

保留 #83 的文件形态与格式门禁,补上流程的两个执行入口:

- **阈值成为常量。** `PROMOTE_AFTER = 3`、`STALE_DAYS = 60` 写进
  `scripts/check_lessons.py`,与 CONTRIBUTING 的表述同源;`--due` 复用同一
  判定,不再各写一份条件。
- **新增 `--report`。** 输出可直接作为 issue 正文的 Markdown:到期升级条目
  (编号 / 标题 / Seen 数 / 证据)、60 天未复发的删除候选、文件体积与下一个
  编号;没有到期条目时输出 `no-lessons-due` 标记。`build_report()` 是纯函数,
  日期与体积由调用方传入,离线测试锚定到期、边界、转义与已升级条目的排除。
- **每周周报工作流。** `.github/workflows/lessons-review.yml` 在北京时间每周一
  01:00(UTC 周日 17:00)运行,也支持 `workflow_dispatch`。它用 `lessons-review`
  标签去重:有到期条目时开一个 issue 或更新已有 issue;没有时关闭旧 issue。
  去重键是标签而不是标题,标题可以被改,标签不会。
- **不阻塞 PR。** 周报只产生 issue,不进入 required checks,也不让无关改动变红。
- **升级与删除仍然只在独立的 `docs(lessons)` PR 里做。** 工作流只负责把到期
  条目摆到台面上;升级要写进 `AGENTS.md`、`CONTRIBUTING.md` 或新 ADR(规则 +
  原因 + 守护用例),条目压成 `### L-001 <标题> → <目标文件>` 的一行指针;
  删除要在 PR 正文说明理由,原文留在 git 历史。

## 备选

- **让到期条目直接把 CI 变红。** 否决:任何无关 PR 都会因为一条历史教训而
  失败,最可能的后果是维护者学会绕过或批量改日期,门禁反而失效。
- **照搬 Tavotto 的分层文件与夜间自动复盘。** 否决:本仓库只有一个文件、
  个位数条目,分层与自动复盘都没有数据支撑;夜间再跑一次也不会有人读。
- **工作流自动删除 60 天未复发的条目。** 否决:删除需要判断「所指代码是否
  已不存在」「是否已有门禁挡住」,这两件事脚本判断不了;自动删除会丢掉仍然
  有效但恰好安静的教训。
- **维持现状,只靠记忆。** 否决:这正是本次要修的问题——机制存在但没有任何
  东西让它运转。

## 后果

- 仓库多一个定时工作流与一个可能长期开着的 issue;这是有意的提醒,不是噪音。
  条目处理完、周报为空后,下一轮会自动关闭它。
- GitHub 会在仓库长期无活动后停用定时工作流;`workflow_dispatch` 是兜底,
  维护者可以手动跑一次。工作流本身不依赖「必须按时跑」才有意义。
- 周报每周消耗一次约 5 分钟的 job,可忽略;它不安装依赖,只跑标准库脚本。
- 升级仍需要一次独立的 `docs(lessons)` PR,因此「到期」到「规则生效」之间
  有一个人工间隔。接受这个间隔:错题本的价值是让规则有证据地收紧,不是让
  流程自动改规则。
- `docs/lessons.md` 的写入纪律不变:功能 PR 不碰该文件;周报工作流只读它。
