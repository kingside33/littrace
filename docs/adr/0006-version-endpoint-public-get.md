# [S3] 版本协商采用公开 GET /api/version,与 /api/session 同级不新增鉴权

- 日期:2026-11-18
- 状态:已接受

## 背景

Zotero 插件在打开工作台之前,需要低成本地探测本地服务是否存在、版本是否兼容。当时的
候选接口都不合适:`/api/v2/meta` 面向前端契约、返回大块枚举语义,拿来握手成本过高;
`/api/session` 只返回 token,拿不到版本号。需要一个「返回 200 即代表服务在线」的轻量
端点,且探测发生在拿到 token 之前。

## 决策

新增公开 `GET /api/version`,返回 `{service_version, api_version: 'v2'}`,挂在
`kbapp/web/system_api.py` 中与 `/api/session` 同级,复用现有 `local_guard` 中间件
(只拦非 GET 的 `x-kb-token`),不新增鉴权、不引入 POST。

定案边界:本 ADR 记录的是**已落地的实现方向**;方案选型的最终确认跟踪于仓库 issue #5,
该 issue 目前仍为 open。`kbapp/web/system_api.py:36-37` 的注释提到的「S0」即指那次确认,
本 ADR 不依赖仓库外材料判定它是否已发生。

## 备选

- **备选 A:扩展 `/api/v2/meta` 增加版本字段**。不选:会改动 `/api/v2/*` 的对外契约,
  且响应体对一次握手来说过重 —— 为省一个端点去污染一个已经稳定的契约,不划算。
- **备选 B:复用 `/api/session` 附带版本**。不选:违反该端点「发放会话 token」的单一
  职责,GET 语义也会混淆(一个既可探测又可发 token 的端点)。

## 后果

插件用一次 GET 就能同时完成存在性与版本判断,失败即可明确禁用入口并给引导。端点公开
意味着版本号对外可读 —— 版本号非敏感信息,这是可接受代价。若 issue #5 最终改选其他方案,
按「定稿不改写」纪律新开 ADR 引用本编号即可,本文件不回头改写。
