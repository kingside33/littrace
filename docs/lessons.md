# 错题本

本文件记录 littrace 犯过的错与值得照抄的做法,以及它们升级为硬规则的路径。
格式与规矩的全文在 [CONTRIBUTING.md](../CONTRIBUTING.md) 的「Lessons(错题本)」
一节;这里只放条目。

- **读**:动手改代码或评审 PR 之前,先读与本次改动相关的条目。
- **写**:只在独立的 `docs(lessons)` PR 里写;功能 PR 不改本文件。
- **升级**:同一条目在 3 个不同日期出现后,把规则写进 `AGENTS.md`、
  `CONTRIBUTING.md` 或新 ADR,条目压缩成一行指针。
- **删除**:所指代码已不存在、已有门禁挡住,或 60 天不复发且硬规则已覆盖。
- **隐私**:公开仓库,不写本机路径、Zotero 数据、个人配置或凭据。

单文件上限 16 KiB。超过时按主题拆分,并同步修改校验脚本与 CI 步骤。

条目格式(下方代码块是示例,不参与解析):

```markdown
### L-001 <一条可执行的规则,不超过 60 字符>
- 类: 别这样
- Seen: 2026-11-12, 2026-11-19
- 为什么: <发生了什么、代价是什么,一段话>
- 证据: #58, #64
```

## 条目

### L-001 PR 变 CONFLICTING 时没有 CI run,那不是绿
- 类: 别这样
- Seen: 2026-11-18
- 为什么: 分支落后 main 产生冲突后,GitHub 无法生成 merge ref,`pull_request`
  事件不会创建运行。看板上一片安静,容易被当成通过;正确做法是在 worktree 内
  merge `origin/main`、按「两边都保留」解决冲突并推送,让 CI 在新 head 上重跑。
- 证据: #28, #31

### L-002 新增测试锚点先回滚到修复前,确认它真的会红
- 类: 别这样
- Seen: 2026-11-18
- 为什么: 只加断言不验证,断言可能恒真,缺陷被改回来测试照样全绿。提交前把源码
  回滚到修复前跑一遍,确认新增断言转红,再恢复源码。
- 证据: #31

### L-003 平台 API 的返回值与载荷以真机实测为准
- 类: 别这样
- Seen: 2026-11-19
- 为什么: 按类型声明与文档推断 `Zotero_Tabs.add` 的返回值与 `data` 载荷,真机行为
  不符,入口直接失效。实测契约后再实现,退路窗口的 iframe 也需要正确的容器类型。
- 证据: #58

### L-004 验证命令只写一套,平台差异用注释说明
- 类: 照这样
- Seen: 2026-11-18
- 为什么: 文档里硬编码单一平台的解释器路径,与 CI 的多平台矩阵矛盾,其他平台的
  会话会在跑测试之前就失败。统一写成 venv 激活后的命令,差异只在注释里说明。
- 证据: #11

### L-005 新增 tests/test_*.cjs 时同步 ci.yml 的两处清单
- 类: 照这样
- Seen: 2026-11-18
- 为什么: 裸 `node --test` 的目录 glob 会把「已跟踪但未登记」的文件掩盖掉。两处
  显式清单加守卫步骤,能在本地与 CI 同时暴露漏登记。
- 证据: #13
